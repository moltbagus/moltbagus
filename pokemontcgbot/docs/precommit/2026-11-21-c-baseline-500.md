# Precommit — C: the 500-match baseline window

Written before the window opened. Nothing in this file was chosen after seeing a
number from it.

## Why

The repo now records which decision path answered each decision and can replay the
corpus offline. What it still lacks is a defensible before/after: every win-rate
claim so far has been a window someone chose after the fact. This precommit fixes
the window first, so the next policy change (M2 state inference, M3 deck rebuild)
can be judged against it instead of against a number picked to flatter it.

## The window

- **Metric:** in-season win rate on `cmwm3cekx011nln01c3gqi0tc` ([TCG] Playground S7),
  counted per settled match by `wr_report.py`.
- **Basis:** every settled match after the boundary below, no exclusions, no
  per-opponent filtering.
- **Boundary:** the first decision record in `~/.arena-tcg-decisions.jsonl` whose
  `policyPath` is not `unknown`. The corpus itself marks the start — no clock, no
  commit hash to argue about later. Records before it are pre-attribution and are
  not part of this window.
- **Sample:** 500 settled matches. The number is reported at 500 and nowhere
  earlier. A smaller window is not a result.
- **Bound:** Wilson 95% lower bound. A point estimate alone does not settle it.

## Baseline, recorded before the window

Measured 2026-11-20 23:53 +08 with `wr_report.py --since 2026-11-20T00:00:00`
(`evidence/wr-report.json`):

| window | matches | W | L | WR | Wilson 95% CI |
|---|---|---|---|---|---|
| S7 to date | 285 | 104 | 181 | 36.49% | [31.12%, 42.23%] |
| lifetime | 319 | 116 | 203 | 36.36% | — |

G1 in the world-class spec (≥46% with a lower bound ≥44%) is not reachable from
this baseline by tuning; it needs the structural work.

## Decision rule, fixed now

1. At 500 matches the number is reported as found. No early stop, no peek-and-extend.
2. No policy or deck change ships inside this window. M2 and M3 are built, tested
   and queued, not deployed, until the window closes.
3. If the 500-match Wilson lower bound falls **below 36.0%** (the pre-window point
   estimate), the intervening work is reverted rather than re-tuned.
4. If it lands between 36.0% and the lower bound of the pre-window CI (31.12%), the
   window is reported as unresolved — no claim either way.
5. Every report names the sample, the bound, the competition id and the commit the
   bot was running.

## What this window cannot tell you

It measures the deployed policy against itself at two points in time. Opponent
strength drifts, the season's population changes, and the deck is locked. A delta
inside this window is evidence about this bot on this board in this season — not a
transferable strength number.
